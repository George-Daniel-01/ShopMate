ShopMate — Postman API Test Collection

Click any endpoint to expand headers, body, and expected response.

Base URL: http://localhost:4000/api/v1

1. Auth 9 endpoints

▶ POST /auth/register Public
Headers
Content-Type: application/json
Body (raw JSON)
{
  "name": "John Doe",
  "email": "john@example.com",
  "password": "12345678"
}
Expected Response // 201 Created
{
  "success": true,
  "user": { "id": "uuid...", "name": "John Doe", "email": "john@example.com", "role": "User" },
  "message": "User registered successfully",
  "token": "jwt_token_here"
}
Note: Password must be 8–16 characters. After registering, save the token for authenticated requests.
▶ POST /auth/register-admin Public
Headers
Content-Type: application/json
Body (raw JSON)
{
  "name": "Admin User",
  "email": "admin@example.com",
  "password": "12345678",
  "adminSecretKey": "your_admin_secret_from_env"
}
Expected Response // 201 Created
{
  "success": true,
  "user": { "role": "Admin", ... },
  "message": "Admin registered successfully",
  "token": "jwt..."
}
Important: adminSecretKey must match ADMIN_SECRET_KEY in your config.env file. Register at least one admin first to test admin-only endpoints.
▶ POST /auth/login Public
Headers
Content-Type: application/json
Body (raw JSON)
{
  "email": "admin@example.com",
  "password": "12345678"
}
Expected Response // 200 OK
{
  "success": true,
  "user": { ... },
  "message": "Logged In.",
  "token": "jwt_token_here"
}
Tip: Copy the token from the response and add it as Authorization: Bearer in Postman for all authenticated routes.

2. Products 7 endpoints

▶ POST /product/admin/create Admin
Headers
Authorization: Bearer 
Content-Type: multipart/form-data
Body (form-data)
name: "iPhone 15"
description: "Latest Apple smartphone with A16 chip"
price: "999.99"
category: "Electronics"
stock: "50"
images: (select one or more image files)
Expected Response // 201 Created
{
  "success": true,
  "message": "Product created successfully.",
  "product": {
    "id": "uuid...",
    "name": "iPhone 15",
    "price": 999.99,
    "category": "Electronics",
    "images": [{ "url": "https://res.cloudinary.com/...", "public_id": "Ecommerce_Product_Images/..." }],
    ...
  }
}
Important: Use form-data not raw JSON — files require multipart upload. Images are uploaded to Cloudinary.
▶ GET /product?page=1&category=Electronics&price=0-10000&ratings=4&search=iphone&availability=in-stock Public
Query Parameters (all optional)
page: 1           // page number (default 1)
category: Electronics // filter by category (ILIKE match)
price: 0-10000     // min-max price range
ratings: 4         // minimum rating
search: iphone      // search in name/description (ILIKE)
availability: in-stock // in-stock | limited | out-of-stock
Expected Response // 200 OK
{
  "success": true,
  "products": [ ... ],
  "totalProducts": 5,
  "newProducts": [ ... ],    // created within last 30 days
  "topRatedProducts": [ ... ] // rating >= 4.5
}
Test simplest: GET /product?page=1 returns first 10 products with no filters.

4. Orders 6 endpoints

▶ POST /order/new Auth
Headers
Authorization: Bearer 
Content-Type: multipart/form-data  // or application/json
Body (form-data or raw JSON)
{
  "full_name": "John Doe",
  "state": "California",
  "city": "Los Angeles",
  "country": "United States",
  "address": "123 Main St, Apt 4B",
  "pincode": "90001",
  "phone": "1234567890",
  "orderedItems": "[{\"product\":{\"id\":\"product-uuid\",\"price\":999.99,\"stock\":50,\"images\":[{\"url\":\"...\",\"public_id\":\"...\"}]},\"quantity\":1}]"
}
Notes
If using form-data, send orderedItems as a string (JSON.stringify).
If using raw JSON, send it as a normal array.
Expected Response // 200 OK
{
  "success": true,
  "message": "Order placed successfully. Please proceed to payment.",
  "orderId": "uuid...",
  "paymentIntent": "pi_...",
  "total_price": 1199.99
}
Key: This creates order + order_items + shipping_info + Stripe payment intent. Save paymentIntent for the Stripe frontend step.

5. Stripe Webhook 1 endpoint

▶ POST /api/v1/payment/webhook Public
Headers
Content-Type: application/json
Stripe-Signature:
Body (raw JSON)
// Send a simulated Stripe event object.
// Best tested via Stripe CLI: stripe trigger payment_intent.succeeded
{
  "id": "evt_test_webhook",
  "type": "payment_intent.succeeded",
  "data": {
    "object": {
      "client_secret": "pi_..._secret_...",
      ...
    }
  }
}
Expected Response // 200 OK
{ "received": true }
Testing locally: Install Stripe CLI, run stripe listen --forward-to localhost:4000/api/v1/payment/webhook, then stripe trigger payment_intent.succeeded.

Recommended Testing Order

  1. POST /auth/register-admin — create your first admin
  2. POST /auth/login — login as admin, save the token
  3. POST /product/admin/create — create a product (form-data with image)
  4. GET /product?page=1 — verify product appears in public listing
  5. POST /auth/register — create a customer user
  6. POST /auth/login — login as customer, save their token
  7. POST /order/new — customer places an order
  8. GET /order/orders/me — customer sees their order
  9. GET /admin/getallusers?page=1 — admin sees customer in list
  10. PUT /order/admin/update/:id — admin changes status to "Shipped"
  11. GET /admin/fetch/dashboard-stats — dashboard shows revenue + stats
  12. DELETE /product/admin/delete/:id — admin deletes product
